# Инструкции для работы с проектом

- Перед нетривиальным изменением прочитайте `PROJECT_CONTEXT.md`.
- Не добавляйте параллельные установщики и не храните старые сборки в `dist/`.
- После каждого апдейта повышайте версию и выпускайте проверенные установщики. Последнее указание пользователя от 24.09.2026 отменяет локальную поставку: публикуйте релиз GitHub, Windows EXE, macOS Universal DMG и Chrome ZIP из одного неизменяемого коммита. Для Chrome Web Store требуется доступ к кабинету издателя; не называйте готовый ZIP опубликованным в Store.
- После изменения версии, состава runtime, структуры, загрузки, хранилища или релизной схемы обновите ручной контекст и выполните `powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/update-project-context.ps1`.
- Последнее указание пользователя от 25.09.2026 требует сокращённого объёма тестов. Для 8.0.17 используйте search-focused: 16 связанных наборов из tests/search-focused-suites.json и проверку контекста. Обе сборки зависят от успеха этого точного профиля на релизном коммите. Полный пакет без нового запроса не запускать.
- После проверенной публикации обновляйте только main/update.json через tools/publish-update-channel.mjs: это канал обоих desktop-updater. Не заменяйте остальные файлы main ради метаданных.
- Указание пользователя от 22.10.2026: каждый релиз обязательно должен появляться в автообновлении. Поставка не завершена, пока tools/publish-update-channel.mjs не подтвердит актуальную версию по публичному URL main/update.json, который читают установленные приложения. При недоступности или старой версии канала исправьте публикацию и повторите проверку.
- После каждого проверенного GitHub Release размещайте Windows EXE, macOS Universal DMG, Chrome ZIP и их `.sha256` в Яндекс Диске: ``Материалы PENA общие/L`Oreal/0_Внутренние материалы/Материалы для задач/Сортировщик чатов /v<версия>/``. Последнее указание пользователя от 14.10.2026 отменяет резерв трёх папок: используйте одну и ту же существующую папку актуальной версии, переименовывайте её в новый номер и заменяйте файлы внутри; саму папку не пересоздавайте. Проверьте новую загрузку до удаления предыдущих файлов и лишних папок версий. Подробный адрес и порядок — в `PROJECT_CONTEXT.md`. GitHub Release остаётся источником артефактов и истории версий.
- Не заявляйте о живой проверке macOS без запуска на реальном Mac.
