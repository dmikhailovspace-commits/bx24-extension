# Подключение портала при первом запуске Chrome-версии

При открытии окна расширения пользователь вводит адрес своего портала Bitrix24. Поле принимает HTTPS-ссылку или доменное имя, приводит её к точному HTTPS-домену и показывает этот домен до запроса доступа. Никакие права не запрашиваются во время ввода или установки: кнопка «Подключить портал» вызывает штатный запрос Chrome по явному нажатию. После разрешения адрес уже сохранён самим Chrome; повторная активация показывает подключённые порталы. Можно отключить один портал, не затрагивая остальные.

Если пользователь уже находится на подключаемом портале, окно предлагает обновить вкладку после сохранения черновиков. Если портал не открыт, окно предлагает открыть его. Автоматически перезагружать или менять открытую страницу нельзя. Существующие Chrome-установки сохраняют выданные права; desktop-версия не меняется.

## План

1. Обновить `chrome/popup.html`, `chrome/popup.css`, `chrome/popup.js`: явное поле адреса, нормализация и ошибки, состояние подключения, открытие портала или безопасное обновление текущей вкладки.
2. Расширить `tests/chrome-popup-regression.mjs` на первый запуск, ввод адреса с путём, отказ/повтор, уже выданный доступ и открытие вкладки. Проверить, что запрос разрешения остаётся непосредственно в обработчике доверенного клика.
3. Поднять версию, обновить документацию для пользователя и `PROJECT_CONTEXT.md`, выполнить только утверждённый профиль `search-focused` и проверку контекста.
4. Выпустить Windows EXE, Universal macOS DMG и Chrome ZIP из одного тега; после проверки обновить GitHub Release, канал desktop-обновления, Яндекс Диск и пакет Chrome Web Store.
