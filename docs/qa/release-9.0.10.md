# Прокрутка ленты и переписки в 9.0.10

В 9.0.8 обработчик колеса для списка стоял на всём документе и мог задержать стандартную прокрутку до завершения JavaScript. Даже в открытой переписке он искал список и его область прокрутки. В 9.0.10 пассивный обработчик закреплён на списке. Отдельный лёгкий сигнал активности по-прежнему останавливает фоновый обход при вмешательстве пользователя.

## Как проверяли

Chromium прокручивал обе области на 1 920 пикселей за 48 событий колеса. Стенд переиспользовал узлы диалогов и заменял узлы сообщений при скролле. Четырёхкратное замедление процессора одинаково для обеих версий. Порядок запусков 9.0.8, 9.0.10, 9.0.10, 9.0.8. Служебный отчёт стенда, который каждые 5 мс читает геометрию страницы, отключён после проверки CPU-профиля. Пользовательский портал в замеры не входил.

| Измерение на 1 600 строках | 9.0.8, два прогона | 9.0.10, два прогона |
|---|---:|---:|
| Интервал кадров при прокрутке ленты, 95-й процентиль | 66,7 / 66,7 мс | 16,8 / 16,8 мс |
| Интервалы больше 50,5 мс в ленте | 9 / 19 | 0 / 0 |
| Суммарное время обработчика списка за 48 событий | 1 867 / 2 121 мс | 8 / 9 мс |
| Поиски по всему документу внутри обработчика ленты | 528 / 528 | 0 / 0 |
| Время обработчика списка при прокрутке переписки | 581 / 618 мс | 0 / 0 мс |
| Интервал кадров при прокрутке переписки, 95-й процентиль | 16,7 / 16,7 мс | 16,8 / 16,7 мс |

На 350 строках время обработки колеса над лентой сократилось с 485–501 до 7–9 мс. В дополнительной проверке установленной Chrome-сборки обе области прокрутились на полные 1 920 пикселей, отменённые два события были восстановлены ровно один раз. Для неё копия манифеста получила доступ к одному тестовому домену. Интервал кадров зависит также от Bitrix и браузера. В этой дополнительной проверке зафиксированы два интервала свыше 50,5 мс в переписке. [Данные всех прогонов](scroll-9.0.10.json)

## Проверка релиза

На коммите `7810a0930bf29ee0caaca9dd0ddac45565eb8a80` локально прошли 16 из 16 наборов профиля `search-focused` за 378,6 секунды. Сценарий прокрутки обеих областей также включён в проверку тега перед сборкой установщиков. [Журнал сборки](https://github.com/dmikhailovspace-commits/bx24-extension/actions/runs/44484028553)

Все четыре задания GitHub Actions прошли. Проверены размеры и SHA-256 опубликованных файлов. Chrome ZIP воспроизведён побайтово из тега. Его SHA-256 — `d9a08f816f63e744b17a267887fcc958dba89985f241fd9dea46b40508065b99`. Локальная Windows-копия исходников содержала окончания строк CRLF. Поэтому для окончательной проверки в Chromium отдельно распаковали ZIP из GitHub Release и добавили в тестовую копию манифеста разрешение на домен стенда. [Файлы релиза](https://github.com/dmikhailovspace-commits/bx24-extension/releases/tag/v9.0.10)

В этом запуске обе области прокрутились на 1 920 пикселей. В ленте 48 вызовов обработчика заняли суммарно 12 мс, без поиска по всему документу и без интервалов длиннее 50,5 мс. В переписке обработчик списка не вызывался, зафиксирован один интервал длиннее 50,5 мс. Два отменённых события по 25 пикселей восстановили суммарное движение на 50 пикселей.

Публичный канал автообновления подтвердил 9.0.10. В общей папке Яндекс Диска проверены Windows EXE, Universal DMG, Chrome ZIP и их контрольные суммы. Кабинет Chrome Web Store подтвердил отправку версии 9.0.10 с автопубликацией после проверки.
