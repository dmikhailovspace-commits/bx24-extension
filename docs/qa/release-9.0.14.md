# Открытие диалогов и прокрутка в 9.0.14

На удалённом Windows-стенде Chromium выполнил один и тот же сценарий с кодом из тега 9.0.13 и из релизного коммита 9.0.14. Использовались синтетические диалоги. [Протокол GitHub Actions](https://github.com/dmikhailovspace-commits/bx24-extension/actions/runs/44522200123)

| Проверка | 9.0.13 | 9.0.14 |
|---|---:|---:|
| Сдвиг сообщения и поля ввода от исходной позиции при движении вниз | −64 px | 0 px |
| Сдвиг от исходной позиции после обратного движения | +36 px | 0 px |
| Позиция во втором чате после запоздалого ответа первого при заданных пользователем 812 px | 700 px | 812 px |
| Лишние переходы через запасной маршрут | 2 | 0 |
| Проверено строк при поиске области прокрутки в ленте из 1600 диалогов | 1600 | 4 |
| Время одного поиска на стенде | 11,8 мс | 6,7 мс |

В сценарии с двумя колонками контейнер ленты временно исчезал, затем возвращался. После его возврата лента прокрутилась на заданные 64 px в обеих версиях. Отдельно проверен отказ от установки панели папок в общий контейнер с перепиской.

В тесте прокрутки Chromium с четырёхкратным замедлением CPU выполнил по 48 движений колеса в ленте и в переписке. Каждая область прошла 1920 px. В обеих 95-й процентиль интервала между кадрами составил 16,7 мс, интервалов свыше 50,5 мс не зафиксировано. При прокрутке переписки обработчик колеса списка вызывался 0 раз.

Сценарий замера запускается командой `node tests/dialog-opening-position.mjs v9.0.13`. Файлы `dialog-opening-position.json` и `native-wheel-performance.json` сохранены в артефакте regression-diagnostics релизной сборки. Процент загрузки CPU установленного Bitrix24 в этом замере не измерялся.
