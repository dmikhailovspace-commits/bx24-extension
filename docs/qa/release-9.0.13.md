# Прокрутка ленты и переписки, 9.0.10 → 9.0.13

При первом открытии папки расширение раньше пересчитывало её содержимое во время ожидания сети. После ответа Bitrix несколько обработчиков заново проходили по ленте. В 9.0.13 сортировщик пропускает фоновую работу на время активной прокрутки, объединяет обработку страницы и собирает данные большого списка порциями. Новые строки сразу получают фильтр выбранной папки.

## Замеры

На четырёх удалённых Windows-раннерах сравнивали неизменяемые теги. Каждый раннер проверял обе версии дважды с чередованием порядка. За проход Chromium получал 144 события колеса на каталоге из 1 200 тестовых диалогов. Стенд задерживал ответ на 950 мс и появление строк ещё на 120 мс. Он проверил фактическое движение нужной области, пересечение ввода с загрузкой и появление целевого диалога в каталоге.

В таблице показан худший интервал между вызовами requestAnimationFrame за два прогона. Число длинных интервалов суммируется за оба прогона, а время работы главного потока усредняется. Последнее включает ожидание завершения обработки после движения. Проценты общей загрузки CPU настольного Bitrix24 этим способом не измеряются.

| Область | Строк в странице | Макс. кадр в движении, мс | Интервалы >50,5 мс в движении | Макс. кадр за весь сценарий, мс | Время работы потока Chromium, мс |
|---|---:|---:|---:|---:|---:|
| Лента | 50 | 33 → 17 | 0 → 0 | 50 → 17 | 434 → 214 (2.03×) |
| Лента | 600 | 483 → 17 | 11 → 0 | 483 → 233 | 1374 → 716 (1.92×) |
| Переписка | 50 | 50 → 17 | 0 → 0 | 67 → 50 | 512 → 381 (1.35×) |
| Переписка | 600 | 750 → 33 | 10 → 0 | 750 → 183 | 1724 → 1120 (1.54×) |

Во время прежнего живого замера в Bitrix24 для Windows с 9.0.10 интервал между показанными кадрами достигал 145 мс в папке и 173 мс в переписке. В той же переписке при выключенном расширении максимум составил 92 мс. Сравнение релизов в таблице проведено полностью на удалённых раннерах.
