# Chrome Web Store: сведения для издателя и проверяющего

Пакет: Сортировщик чатов Bitrix24 Chrome 7.5.117. Этот документ описывает сборку и сценарий проверки; он не свидетельствует о прохождении проверки Store или работе на реальном портале. До отправки издатель должен выполнить сценарий на выделенном HTTPS-портале и заполнить закрытое поле Test instructions реальными реквизитами доступа.

## Разрешения

| Разрешение | Назначение |
| --- | --- |
| `storage` | Локальный кеш каталога, настройки включения и список подключений; синхронизация вкладок одного профиля. |
| `unlimitedStorage` | Каталоги больших порталов и их безопасное обновление с сохранением предыдущего поколения могут превышать стандартную квоту `storage.local`. Разрешение не означает неограниченную память и не используется для скачивания вложений. |
| `activeTab` | По нажатию значка определить адрес текущей вкладки и предложить подключить именно её портал. Постоянная история вкладок не собирается. |
| `scripting` | Зарегистрировать и запустить входящие в пакет скрипты и стили на разрешённом портале, включая нужные фреймы Bitrix24. |
| `optional_host_permissions: https://*/*` | Возможность запросить конкретный HTTPS-хост, заранее неизвестный разработчику: Bitrix24 работает на адресах клиентов. При подключении запрашивается выбранный хост, а не все сайты. Chrome не ограничивает разрешение отдельным портом. |

Состав разрешений следует сверять с **собранным** `chrome-release/unpacked/manifest.json`, а не с настольным `extension/manifest.json`. [Принцип минимальных разрешений](https://developer.chrome.com/docs/extensions/develop/concepts/declare-permissions).

## Privacy practices в кабинете

Single purpose возьмите из `STORE-LISTING.ru.md`. Укажите публичный URL окончательной `PRIVACY.md` и раскройте локальную обработку: [официальный FAQ](https://developer.chrome.com/docs/webstore/program-policies/user-data-faq) прямо относит её к обработке пользовательских данных.

Для фактического поведения нужны следующие категории, с учётом формулировок текущего кабинета:

- **Personally identifiable information:** ID пользователей, участников, имена, адреса порталов.
- **Personal communications:** фрагменты сообщений и сведения об авторах для списка чатов.
- **Website content:** названия задач, проектов, статусы, записи времени и комментарии.
- **User activity:** взаимодействия с задачей, собственная отправка сообщения, таймер и контакты.
- **Web history:** текущий адрес разрешённого портала и URL задачи, когда они нужны интеграции; общего журнала посещений нет.
- **Authentication information:** существующая сессия/SDK и `sessid` используются для запросов к Bitrix24; пароль не запрашивается и токен не сохраняется в отдельной базе расширения.

Финансовые и медицинские данные не являются целевыми полями расширения; пользовательский текст может содержать произвольные сведения. Нельзя писать «никакие данные не обрабатываются» только потому, что у разработчика нет сервера аналитики. Подтверждения об использовании и передаче данных должны соответствовать опубликованной политике. [Заполнение privacy-полей](https://developer.chrome.com/docs/webstore/cws-dashboard-privacy).

Удалённый исполняемый код: **не используется**. Исполняемые файлы поставляются в ZIP; вызовы существующего SDK Bitrix24 используют интерфейс страницы и возвращают данные. Шрифты и значки локальные. Chrome-вариант не загружает обновления с GitHub и не показывает настольную ссылку на `bx24.id-pr.ru`.

## Доступ для проверки

В закрытом поле Test instructions предоставьте адрес тестового HTTPS-портала, отдельный логин, пароль и понятный способ входа при наличии дополнительных проверок. В репозиторий и публичную карточку эти сведения не добавляются. [Поле Test instructions](https://developer.chrome.com/docs/webstore/cws-dashboard-test-instructions).

Подготовьте демонстрационные данные: два доступных проекта, задачи с включённым учётом времени, одну задачу без учёта времени, обычный чат, чат задачи и несколько собственных записей времени. Учётная запись должна иметь права на добавление, редактирование и удаление своих записей. Используйте тестовые сообщения и задачи, а не рабочие данные клиентов. Не давайте администраторские права без необходимости.

## Сценарий

1. Установить ZIP как распакованное расширение либо установить проверяемую Store-сборку. Открыть окно расширения на постороннем сайте: интеграция Bitrix24 не должна появляться сама.
2. Войти в подготовленный HTTPS-портал. Через окно расширения разрешить доступ к показанному хосту и перезагрузить вкладку. Открыть «Чаты», дождаться начальной загрузки, проверить обычное открытие и отправку тестового сообщения.
3. Создать папку, переместить в неё тестовый диалог, назначить цвет, проверить случайный цвет и поиск. Перезагрузить страницу: настройки сохраняются. Проверить «Чаты задач» и переключение обратно.
4. Открыть панель времени. При первой настройке выбрать один проект и сохранить. Проверить, что задачи другого проекта не предлагаются для новой записи. Изменить выбор проектов и проверить обновление списка.
5. Найти задачу по названию, ввести одну минуту и сохранить. Проверить запись в панели и в Bitrix24. Изменить её, затем удалить. Неопределённый ответ сервера должен предлагать сверку, а не бесконтрольное повторное добавление.
6. В нижней части панели найти задачу, запустить таймер, подождать и остановить с сохранением. Проверить собственную запись в Bitrix24. Кнопка ручного обновления статична; состояние чтения показывается отдельно.
7. Открыть задачу с учётом времени и оставить видимой не менее 60 секунд либо отправить собственное тестовое сообщение в её чате. Проверить локальный контакт. Входящее сообщение и краткий просмотр не должны создавать контакт. Контакты сами не добавляют время в серверный журнал.
8. Добавить время к этой задаче: учтённые контакты скрываются. После нового квалифицированного контакта задача появляется с уже учтённым временем и числом новых контактов.
9. Перезагрузить портал: сохранённый сегодняшний итог может показаться сразу, затем подтверждается загрузкой. Проверить узкое окно, закрытие панели, повторное открытие и работу обычного интерфейса Bitrix24.
10. Отозвать доступ в настройках Chrome и перезагрузить портал. Интеграция больше не запускается. Отключение не удаляет серверные записи и не является очисткой локальной истории.

## Границы проверки

Локальные Chromium-стенды проверяют поведение контролируемых ответов и интерфейса. Они не доказывают доступность API на каждом клиентском портале, работу конкретного SSO, совместимость всех редакций Bitrix24 или будущую скорость в Chrome Web Store. В опубликованном описании не должны появляться гарантии Store-одобрения и универсального ускорения.

Перед отправкой ещё нужны: фактические сведения об издателе, контакт поддержки, публичная политика, доступ проверяющего и реальные изображения Chrome-сборки. [Правила Chrome Web Store](https://developer.chrome.com/docs/webstore/program-policies/policies), [процесс проверки](https://developer.chrome.com/docs/webstore/review-process).
