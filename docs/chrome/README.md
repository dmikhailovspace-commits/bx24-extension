# Сортировщик чатов Bitrix24 для Google Chrome

Chrome-сборка 8.0.4 предназначена для веб-интерфейса Bitrix24 в Chrome 106 и новее. Она устанавливается отдельно от настольной версии и получает доступ к каждому HTTPS-порталу по вашему разрешению. HTTP-порталы не поддерживаются: для сохранения контактов нужны защищённый контекст и Web Locks.

Настройки из отдельного профиля настольного Bitrix24 автоматически не переносятся. При переходе с распакованной версии на Store меняется ID расширения и его собственное хранилище Chrome; это отдельная установка. Уже внесённое на сервер время остаётся в Bitrix24.

## Установка без Chrome Web Store

1. Распакуйте `chrome-release/BX24_Chat_Sorter_Chrome_v8.0.4.zip` в постоянную папку. При сборке из исходников готовая папка уже находится в `chrome-release/unpacked/`.
2. Откройте `chrome://extensions`, включите «Режим разработчика», нажмите «Загрузить распакованное расширение» и выберите папку, внутри которой лежит `manifest.json`.
3. Откройте свой HTTPS-портал Bitrix24 и войдите в обычную учётную запись.
4. Откройте окно расширения через значок Chrome, проверьте адрес портала и разрешите подключение к этому сайту. Для другого портала разрешение нужно выдать отдельно.
5. Сохраните черновики и нажмите «Обновить вкладку» в окне расширения. Откройте «Чаты» или «Чаты задач». Для учёта времени откройте панель расширения и выберите проекты. До сохранения этого выбора расширение не загружает трудозатраты.

Это стандартная [установка распакованного расширения](https://developer.chrome.com/docs/extensions/get-started/tutorial/hello-world#load-unpacked). Не выбирайте исходную папку `extension/`: в ней находится вариант для настольного Bitrix24 с другим загрузчиком и разрешениями.

Разрешение Chrome относится к HTTPS-хосту целиком, включая его пути; оно не ограничивается одной страницей и не разделяет порты. Поддомены подключаются отдельно. На сайтах без выданного разрешения расширение не запускает интеграцию.

## Обновление, отключение и данные

Для обновления распакованной версии замените файлы в той же папке, нажмите «Обновить» на карточке в `chrome://extensions` и перезагрузите вкладки Bitrix24. Не удаляйте расширение ради обновления: удаление очищает его собственное хранилище. Установленная через Store версия обновляется средствами Chrome; встроенного GitHub-проверяющего в этой сборке нет.

Доступ к сайту можно отозвать в настройках расширения. После отзыва или отключения перезагрузите уже открытые вкладки, чтобы убрать ранее запущенную интеграцию. Отключение не стирает настройки и журнал. Удаление расширения не удаляет записи времени из Bitrix24 и не очищает его `localStorage` на портале. Подробности — в [политике конфиденциальности](PRIVACY.md).

Первичная загрузка зависит от объёма доступных чатов, задач и ответа портала. Старый сохранённый итог может появиться раньше свежего ответа; статус панели показывает проверку. «Контакты» в панели — подтверждённые взаимодействия с задачей, а не адресная книга CRM. Они сами по себе не добавляют часы в Bitrix24.

## Сборка из исходников

Из корня проекта:

```powershell
node tools/build-chrome.mjs
```

Результат: `chrome-release/unpacked/`, ZIP для загрузки в Store, архив `Chrome_Web_Store_Materials_v8.0.4.zip` и копии документов в `chrome-release/publishing/`. В `publishing/privacy.html` находится готовая HTML-страница политики для размещения на сайте. Настольные EXE/DMG в `dist/` этим процессом не заменяются. Перед передачей новой сборки выполните проверки проекта, включая `pnpm test` и `tools/update-project-context.ps1 -Check`; результат сборки сам по себе не доказывает прохождение проверок.

## Публикация

1. Зарегистрируйте аккаунт издателя и заполните его реальные контактные данные. Google требует регистрационный платёж; его текущие условия показывает кабинет. [Регистрация издателя](https://developer.chrome.com/docs/webstore/register).
2. Опубликуйте окончательную версию `PRIVACY.md` по доступному без входа HTTPS-адресу, добавив реальные сведения об издателе и контакте. Локальный Markdown-файл не заменяет публичный URL.
3. Используйте изображения из `publishing/assets/`: значок 128×128, два скриншота работающей Chrome-сборки на демонстрационных данных 1280×800 и промоплитку 440×280. Скриншоты помечены как демонстрационные; они не подтверждают проверку на вашем портале. [Требования к изображениям](https://developer.chrome.com/docs/webstore/images).
4. В Developer Dashboard создайте новое расширение и загрузите ZIP. Заполните описание из `STORE-LISTING.ru.md`, сведения о данных и разрешениях из `REVIEWER-NOTES.md`, публичную политику и параметры распространения. [Публикация ZIP](https://developer.chrome.com/docs/webstore/publish), [поля конфиденциальности](https://developer.chrome.com/docs/webstore/cws-dashboard-privacy).
5. Передайте проверяющему отдельную тестовую учётную запись Bitrix24 и сценарий из `REVIEWER-NOTES.md` через закрытое поле Test instructions. Пароли не должны попадать в ZIP, репозиторий или публичное описание. [Инструкции для проверки](https://developer.chrome.com/docs/webstore/cws-dashboard-test-instructions).
6. Проверьте тексты и загруженный пакет, затем отправьте на рассмотрение. При необходимости выберите отложенную публикацию. Подготовка этих файлов не означает отправку в Store или одобрение Google.

Издатель должен предоставить вне кода: аккаунт публикации, публичный privacy URL, действующий контакт и тестовый HTTPS-портал с доступом проверяющего. Проверку на реальном портале и решение Chrome Web Store нельзя подменять результатами локальных стендов.

Официальные инструкции проверены 8 сентября 2026 года. Перед отправкой сверяйте обязательные поля с текущим кабинетом.
