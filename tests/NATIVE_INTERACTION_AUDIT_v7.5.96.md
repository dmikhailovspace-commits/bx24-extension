# Влияние PENA на основной интерфейс Bitrix24 — аудит 7.5.96

База: опубликованная `v7.5.95`, commit `41d5a42fde992818a66ac5186c06d71f9653737d`. Пользователь подтвердил задержку поиска упоминаний именно на этой установленной версии. Исходный runtime сохранён отдельно для воспроизводимых сравнений.

Нативные запросы упоминаний не проходят через очередь PENA, их ответы не подменяются. Обработчики поиска расширения ограничены поиском собственного нативного списка. Актуальная проверка разрешения учёта времени перед новым контактом и записью времени сохранена.

## Проверка скорости и её границы

Браузерный A/B-стенд использует настоящий HTTP с контролируемым ответом 80 мс, CPU ×4, историю из 4000 элементов и popup на 240 строк. В каждом плече выполняются по 20 поисков упоминаний, поисков сотрудников, отправок и открытий задачи. Измеряются завершение запроса, возможность отрисовки следующего кадра, работа наблюдателей и запросы PENA.

На старой версии пятисекундная задержка в этом стенде не воспроизвелась: p95 завершения поиска упоминаний составил 120,1 мс без расширения и 124,2 мс с ним; отрисовка — 154,6 и 160,4 мс. Это ограничивает выводы: обнаруженные перехват ввода и лишняя работа подтверждены, универсальное ускорение живого Bitrix не доказано.

Отрицательный контроль намеренно блокирует поток наблюдателем popup: тест обнаруживает превышение тех же бюджетов, которые применяются к расширению. Cold-сценарий отдельно подтверждает доставку настоящего пользовательского ввода Bitrix при отсутствующей шапке. Нативная логика селектора и серверные ответы здесь являются моделью; это не запись живого пользовательского портала.

Для каждого действия и каждой метрики финальный допуск — максимум из p95 контрольного плеча ×1,35 и p95 +50 мс. Это учитывает наблюдавшуюся межзапусковую вариативность контрольного плеча до 19,9 мс, но не пропускает прибавку порядка сотен миллисекунд. Каждый глобальный observer ограничен `3 × число завершённых действий + 20` доставками: штатный сценарий даёт 120 доставок на 80 действий; промежуточный цикл с 986 доставками этот предел нарушает.

После исправлений контрольный прогон дал 80 поисков по DOM вместо 76 920 и 92,5 мс суммарной работы observer вместо 244,5 мс. HTML/BODY получили по 120 доставок; цикл исчез. Поиск упоминаний: p95 до отрисовки 142,4 мс без расширения и 163,1 мс с ним. Вариативность кадров полностью не устранена: доля кадров дольше 25 мс — 1,7%/5,6%. Длительных задач главного потока нет в обоих плечах. Полный отчёт этого прогона сохранён как `tests/artifacts/native-mention-reviewed-fix.json`; результаты полного релизного прогона сохраняются отдельно.

## Воспроизводимость

- `mention-search-ownership-regression.mjs`: принадлежность поиска, доставка событий и группировка изменений списка.
- `toolbar-discovery-regression.mjs`: отсутствие поиска по popup при подключённой шапке, замена и позднее появление шапки.
- `native-mention-interference-regression.mjs`: HTTP/отрисовка A/B, наблюдатели, отрицательный контроль и холодный старт без поля поиска списка.
- `time-candidate-performance-regression.mjs`: число обходов и точное совпадение данных, появление новых названий и чатов на следующей перерисовке.
- `time-refresh-regression.mjs`: пакетная загрузка названий, отмена и частичные ответы вместе с прежними сценариями времени.
- `dialog-repository-regression.mjs`: одна выполняющаяся запись, изменения во время ожидания, ошибка и смена scope вместе с прежними проверками CAS.

Точные JSON-отчёты находятся в `tests/artifacts/`. Полная сводка `regression-summary.json` содержит длительность каждого набора, ошибки и SHA-256 всего runtime. Данные старых неуспешных и диагностических прогонов сохраняются отдельно.

Подход сверялся с рекомендациями Chrome по [освобождению главного потока](https://developer.chrome.com/blog/use-scheduler-yield?hl=en) и официальными [лимитами Bitrix24](https://apidocs.bitrix24.com/limits.html). Пакетирование снижает транспортную нагрузку, но не отменяет стоимость вложенных методов для сервера.
