# Проверка загрузки времени 7.5.110

Одинаковый набор для двух версий: 4149 задач, 108 нативных чатов, 321 запись текущего пользователя, сумма 19260 секунд. Каждый тринадцатый task и последняя задача имеют запись. В обеих версиях SDK сообщает одно и то же поле `timeSpentInLogs`: 60 для этих задач и null для остальных. Пользователь, день и проекты одинаковые; выбраны все проекты и задачи без проекта.

## Протокол

`native-startup-time-contention.mjs` запускает настоящий Chromium, нативную материализацию контролируемого списка, production загрузчик/панель, доверенный ввод и HTTP с задержкой 80 ms. CPU ограничен в 4 раза. Старый runtime берётся из неизменённого commit `812ee8a26473bcd6fa7d3c45067cee6c116d4902`; для обоих запусков используется одинаковый текущий harness.

Сравнивается время от запуска страницы до полного сегодняшнего снимка при закрытой панели. Функциональная проверка требует все 4149 task IDs, все 321 entry IDs, точную сумму, один общий каталог и неизменную полноту нативного списка. Повторное открытие не запускает elapsed/full catalog. Отдельный вариант проверяет выбранный проект, ошибки API и взаимодействие с вводом.

| Показатель | 7.5.109 | Новый путь |
|---|---:|---:|
| Полный сегодняшний снимок | 79866.2 ms | 3538.0 ms |
| Запросы журналов задач | 4149 | 321 |
| Записей / секунд | 321 / 19260 | 321 / 19260 |
| Функциональные фазы | 10 PASS | 10 PASS |

Ускорение полного запуска: **22.57x**. Это не сокращение числа выбранных проектов. Пропускаются только журналы, отсутствие которых подтвердил API; zero-duration записи не пропускаются. Поле общего времени задачи не используется как персональный дневной итог.

Артефакты: `tests/artifacts/native-startup-time-baseline109-same-workload.json`, `native-startup-time-optimized110-final.json`. В полном gate старый missing-field путь и новый путь запускаются отдельными suites. Измерение на управляемом стенде не подтверждает такую же задержку живого портала, скорость его базы данных или физический Mac.

## Ошибки, против которых добавлены регрессии

- Повтор/пропуск ID, неверные границы, частичный пакет, дырка в массиве ответов, смена пользователя и исчезновение доступа во время чтения.
- Старый null-каталог после подтверждённого ADD: сумма не должна откатиться с 180 до 0.
- Переход null к числу без изменения CHANGED_DATE: один GET, затем warm cache.
- Null, 0, "0", undefined и отсутствующее поле имеют разные контракты.
- Preview другого пользователя/проекта/дня, повторы entry IDs, несогласованные даты, переполнение и отказ localStorage.
- Случайный цвет, занятый пустой папкой/другим списком, похожий текущий цвет и горизонтальный сдвиг палитры.

Источники API: [tasks.task.list](https://apidocs.bitrix24.com/api-reference/tasks/tasks-task-list.html), [elapseditem.getlist](https://apidocs.bitrix24.com/api-reference/tasks/elapsed-item/task-elapsed-item-get-list.html), [семантика timeSpentInLogs](https://vibecode.bitrix24.com/docs/entities/tasks/fields). Глобальный непроверенный `getlist(0)`, guessed AJAX action и отдельный Vibecode API с чужими ключами не используются.
